# Value Plan Artifacts

Use these artifacts to make a value creation plan operational rather than a list of ideas.

## Value Bridge

| Bridge element | Question to answer | Evidence needed |
| --- | --- | --- |
| Baseline | What is the agreed starting point, period, scope, and source? | Finance-approved management data |
| Gross benefit | What changes in price, volume, cost, mix, working capital, or risk? | Driver model and operating evidence |
| Cost to achieve | What one-off investment is required? | Delivery plan, vendor quotes, staffing plan |
| Run cost | What ongoing people, technology, or service cost remains? | Operating model and budget |
| Net value | What remains after all costs and disbenefits? | Reconciled financial bridge |
| Timing | When will leading and lagging indicators move? | Milestone plan and implementation evidence |

## Initiative Design Standard

An initiative is ready to enter the committed plan only when it has:

- One accountable executive owner and one delivery lead.
- A named baseline and leading indicator.
- A specific value mechanism and non-overlapping benefit calculation.
- A dated next milestone, dependency list, and escalation path.
- A defined confidence level and a test for the most material assumption.

If any element is missing, label the work as a hypothesis-validation sprint rather than a committed benefit.

## 100-Day Review Cadence

| Cadence | Participants | Decisions | Minimum artifact |
| --- | --- | --- | --- |
| Weekly initiative review | Owner, delivery lead, workstream team | Remove blockers; confirm milestones | Initiative card and action log |
| Biweekly cross-functional review | Workstream owners, transformation lead | Resolve dependencies and benefit overlap | Integrated roadmap and risk log |
| Monthly value review | Sponsor, finance, initiative owners | Validate forecast and revise plan | Benefits Tracker and value bridge |
| Day-100 steering review | Sponsor, executive team, finance | Fund, scale, stop, or redesign next wave | Executive value review |

## Common Failure Modes

- Starting with a target number without agreeing the baseline or calculation method.
- Letting multiple teams claim the same revenue, savings, or capacity benefit.
- Counting gross savings while omitting implementation, run-rate, or service-level costs.
- Publishing an initiative list without owners, milestones, or leading indicators.
- Treating an activity milestone as proof that a financial outcome has occurred.
- Escalating only late-stage delivery problems instead of the assumptions and dependencies that cause them.
